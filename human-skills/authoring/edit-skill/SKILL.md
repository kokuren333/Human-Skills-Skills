# Human Skillを読みやすく直す

## こんなとき

既存のHuman Skillを、内容は保ちながら分かりやすくしたい、文章を修正・編集したい、検索しやすくしたい、情報を追加または整理したいときに使います。

特に、文章が詰まっている、内容が薄い、手順が曖昧、一般論だけで学びが少ない、Agent向けの命令文のようになっている、見出しや改行が不自然といった問題を直す場合に向いています。

## どうする

編集前に全体を読み、「誰が、どんな状況で、何を理解または実行できるようになるためのSkillか」を一文で説明できる状態にします。目的を確認せずに文章だけ整えると、見た目はきれいでも別のSkillに変わってしまうことがあります。

既存のexport済みSkillに有効な `id` と `author` が含まれている場合は、原則そのまま保持します。単なる改稿、タイトル改善、移動、誤字修正ではIDを変えません。新しいYAMLキーや独自メタデータは追加せず、Human Skillsの既存フォーマットを維持します。

文章を短くする前に、内容の密度を確認します。次のような状態なら、削るより先に内容を補強します。

- 結論だけで理由がない
- 「意識する」「工夫する」「継続する」など抽象的な助言しかない
- 何を観察して判断するのか分からない
- どの条件で方法を変えるのか分からない
- 例がなく、実際の場面を想像できない
- 失敗しやすい内容なのに失敗条件が書かれていない
- 読む前と後で、読者の判断材料がほとんど増えない

補強するときは、背景知識を無制限に足すのではなく、実際の理解や判断を変える情報を優先します。なぜその方法が働くのか、どこを観察するのか、良い例と悪い例は何が違うのか、どこまで適用できるのか、といった要素を追加します。

同時に、同じ内容の繰り返し、長い前置き、元資料固有の説明、読者の判断に影響しない背景は削ります。「適切に対応する」のような曖昧な箇所は、可能なら具体的な判断条件へ置き換えます。

本文は `## こんなとき`、`## どうする`、必要なら `## 補足` の構成を維持します。これらの区画の中で `###` などの追加見出しは使いません。内容が長い場合は、段落、箇条書き、必要な場合だけ番号付きリストで整理します。

見出しの直後には空行を入れ、段落同士も空行で分けます。本文の途中で1文ごとに改行されている場合は、同じ話題を自然な段落へ戻します。逆に、複数の話題が一つの巨大段落になっている場合は、段落や箇条書きで分けます。

タイトルや `こんなとき` には、読者が実際に使いそうな言葉があるか確認します。検索語だけを並べるのではなく、状況説明の文章として自然に含めます。

元資料や特定人物から作られたSkillであっても、由来を示すための人物名、出典人物、`derived_from` などを新たに追加しません。完成したSkillは、それ単体で匿名のHuman Skillとして読める状態を優先します。

編集後は、次を確認します。

- 何を学べるSkillなのか明確か
- 読む前より具体的な判断や行動ができるか
- 内容を削りすぎて標語やTipsになっていないか
- 重要でない説明を残しすぎて核心が埋もれていないか
- `##` 内に追加見出しが入っていないか
- 元のSkillの目的やidentityを不必要に変えていないか

## 補足

Human Skillの編集では、短さそのものを品質指標にしません。「見つけやすい」「読んで意味が分かる」「学ぶ価値がある」「実際に使える」の4点を同時に満たすことを優先します。
