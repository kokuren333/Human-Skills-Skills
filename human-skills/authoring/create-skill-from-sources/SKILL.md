# 資料からHuman Skillを作る

## こんなとき

Web記事、論文、マニュアル、本、動画の文字起こし、社内資料、自分のメモなどを参考にして、再利用可能なHuman Skillを作りたいときに使います。

資料の要約を作るのではなく、複数の情報から、読者が実際に学べる考え方、判断基準、手順、失敗からの戻り方などを取り出したい場合に向いています。

## どうする

資料を読み始める前に、最終的に読者が何を理解し、何をできるようになるSkillなのかを決めます。目的を決めずに資料を集めると、情報量だけが多い要約集になりやすくなります。

資料からは、事実だけでなく「使える構造」を探します。特に次のような情報を優先します。

- 原理や因果関係
- 手順や順序
- 判断基準
- 前提条件
- 状況によって結果が変わる条件
- 成功または失敗を確認する方法
- よくある失敗と、その原因
- 失敗から戻る方法
- 例外や限界
- 原則がよく分かる具体例や反例

重要な概念が出てきた場合は、用語だけ抜き出さず、「それを理解すると何を見分けられるようになるか」まで整理します。歴史、背景、逸話、ブランド固有の説明などは、それが判断や理解を変える場合だけ残します。

複数資料が同じことを言っている場合は、共通部分を一つの原則へまとめます。ただし、共通項だけを残して内容を薄くしすぎないようにします。各資料が示している条件、理由、例外、具体例のうち、理解を深めるものは残します。

内容が食い違う場合は、どちらかを雑に捨てず、「前提が違うのか」「対象が違うのか」「条件によって使い分けるのか」「単に証拠が不足しているのか」を確認します。判断できない場合は、不確実性そのものをSkillの中で分かるようにします。

資料に書いてある結論をそのまま短く言い換えただけではHuman Skillにしません。読者がその結論を自力で使えるように、なぜそうなるのか、何を見ればよいのか、どこで判断を変えるのかまで再構成します。

たとえば「初心者は簡単な課題から始めるべき」という資料があっても、それだけでは薄すぎます。簡単な課題から始めることで何を学習できるのか、難易度を上げる目安は何か、簡単すぎる課題を続ける問題は何か、失敗した場合に難易度をどう戻すかまで分かれば、再利用可能なSkillになります。

元資料の文章や人物の表現をそのまま残す必要はありません。資料が手元になくても読者が理解できる、独立したHuman Skillとして書き直します。長い引用や出典一覧は、ユーザーから必要だと指定された場合だけ追加します。

生成するSkillには、元資料の作者、思想家、著者、作品名などを由来情報として埋め込む必要はありません。特定人物の著作から抽出した場合でも、完成したSkillはHuman Skills上で匿名の独立した知識として成立させます。元資料の人物名が内容理解に不可欠な題材だけは、通常の本文情報として扱えますが、由来を示すためだけには入れません。

Human Skillsの既存フォーマットを勝手に拡張しません。新しいYAMLキー、出典管理用の独自メタデータ、`derived_from` のような項目を追加しません。新規Skillでは `id` と `author` を生成せず、既存exportを編集する場合だけ既存値を保持します。

本文は `## こんなとき`、`## どうする`、必要なら `## 補足` で構成し、それぞれの内部で `###` などの追加見出しは使いません。長い内容は段落、箇条書き、番号付きリストで整理します。

完成後は、資料を閉じてSkill単体だけを読み、次を確認します。

- どんなときに使うか分かるか
- 読む前より、対象について具体的に考えられるようになるか
- 「なぜ」「何を見る」「どう判断する」のどれかが十分に説明されているか
- 実際に試せるやり方や適用例があるか
- 重要な例外、失敗条件、トレードオフが抜けていないか
- 元資料の要約を知らなくても意味が通るか
- 「努力する」「意識する」「柔軟に考える」のような一般論だけになっていないか

内容が薄い場合は、無理に一つのSkillとして完成扱いにしません。追加資料を調べる、原理や具体例を掘り下げる、近い候補と統合する、または公開対象から外します。

## 補足

この作業は資料を短く圧縮することではなく、資料に散らばった知識を、別の人が学び直せる形へ編集する作業です。

読みやすさのために短くすることと、学習に必要な内容を削ることは別です。Human Skillとしての価値が薄くなるなら、無理に短文化しないでください。
